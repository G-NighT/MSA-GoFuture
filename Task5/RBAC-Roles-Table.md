# RBAC: роли и уровни доступа (multi-tenant)

Нотация:

- ✅ - разрешено
- ❌ - запрещено
- ⚠️ - ограничено/только агрегировано
- ⭐ - доступ только в пределах `tenant_id` пользователя

| Роль                 | Где используется   | Пользователи/учётки  | Доступ к данным                              | Основные права                                                                   |
| -------------------- | ------------------ | -------------------- | -------------------------------------------- | -------------------------------------------------------------------------------- |
| Platform Super Admin | Платформа GoFuture | SRE/Platform         | ⚠️ агрегировано по всем tenant + break-glass | Управление платформой, глобальные настройки, аварийный доступ по процедуре       |
| Platform SRE         | Платформа          | SRE                  | ⚠️ техметрики/логи (без PII)                 | Мониторинг, инциденты, SLO, перезапуски, масштабирование                         |
| Tenant Admin         | Тенант             | Админ партнёра       | ✅ ⭐ (вкл. пользователи)                    | Управление пользователями, SSO-настройки, конфиги, ключи, лимиты (в рамках квот) |
| Tenant Operator      | Тенант             | Операторы партнёра   | ✅ ⭐ (операционные данные)                  | Просмотр поездок/статусов, поддержка, ограниченные действия (например, отмена)   |
| Tenant Analyst (BI)  | Тенант             | Аналитики партнёра   | ⚠️ ⭐, без PII или в обезличенном виде       | Доступ к витринам BI, отчёты, выгрузки                                           |
| Tenant Developer     | Тенант             | Разработчик партнёра | ✅ ⭐ через API, ❌ к raw данным             | Доступ к API, настройка интеграций, webhooks, ключи (scoped)                     |
| Finance Officer      | Тенант             | Финансы партнёра     | ✅ фин. данные ⭐ (частично)                 | Счета/выплаты/реестры, отчёты, ограничения на PII                                |
| Support Agent        | Тенант             | Поддержка            | ⚠️ ⭐, минимально необходимое                | Просмотр статусов, коммуникация, без доступа к платёжным реквизитам              |
| Service Account      | Машинный доступ    | Сервисы/интеграции   | ✅ строго scoped                             | Client-credentials, доступ по scopes к конкретным API/топикам                    |

## Примечания по безопасности

- Любой доступ к PII/платежам через “least privilege”, аудит и маскирование.
- Для shared DB включаем RLS и автоматические тесты на изоляцию (negative tests).
- В JWT обязательно: tenant_id, roles, scopes, region (если нужно) + trace/correlation для аудита.
