# MSA-GoFuture — итоговый проект (архитектура)

Репозиторий содержит решения по 5 заданиям итогового проекта для кейса GoFuture (переход от монолита к микросервисной архитектуре, event-driven платформа, multi-region HA, data/ML платформа и мультитенантность).

## Структура и результаты

### Task1 — Проектируем домены

Цель: план декомпозиции монолита на доменные сервисы с минимизацией downtime.

Состав артефактов:

- `ADR-001-Domain-Decomposition.md` — нефункциональные требования, карта сервисов и поэтапный план декомпозиции (на год), приоритеты с обоснованием, обратная совместимость.
- `ToBe-C2.puml` — To-Be диаграмма уровня C2 (микросервисы + механизмы backward compatibility).
- `ADR-002-Data-Migration-Plan.md` — план миграции данных по сервисам (под большой объём и минимальный downtime).

---

### Task2 — Event-Driven архитектура (GoFuture)

Цель: событийная платформа для real-time обработки (500k конкурентных поездок), топики Kafka, Saga, надежная доставка и мониторинг.

Состав артефактов:

- `ADR-003-Event-Driven-Platform.md` — модель доменных событий, Kafka-топики/партиционирование по регионам, Saga, надёжная доставка, мониторинг и метрики.
- `ToBe-EventPlatform-C2.puml` — C2 диаграмма событийной платформы с интегрированным мониторингом.

---

### Task3 — Обеспечиваем высокую нагрузку (Global HA, 99.99%)

Цель: глобальное развёртывание в 3+ регионах, геомаршрутизация, репликация данных, failover/DR, комплаенс + инструменты защиты (WAF/Firewall).

Важно: изменения на диаграммах выделены красным.

Состав артефактов:

- `ADR-004-Global-Deployment-HA.md` — выбор регионов, геомаршрутизация, репликация данных, DR/failover, комплаенс, обоснование WAF/Firewall.
- `ToBe-Global-C2.puml` — обновлённая C2 диаграмма (глобальный ландшафт + security), все изменения выделены красным.
- `Replication-Scheme.puml` — схема репликации данных и событий между регионами (красным — элементы репликации).
- `GeoRouting-Scheme.puml` — схема геомаршрутизации пользователей к ближайшему региону (красным — edge/geo-routing компоненты).
- `Failover-Deployment-C4.puml` — C4 deployment диаграмма аварийного переключения + точки отказа (красным — механизмы переключения/DR).

---

### Task4 — Платформа данных для ML и BI (сбор из микросервисов)

Цель: единая схема сбора данных из микросервисов с интеграцией в ML-платформу и BI-инструменты + механизмы качества данных.

Состав артефактов:

- `ADR-005-Data-Platform-ML-BI.md` — описание пайплайна данных и выбор механизмов качества данных.
- `DataPipeline-C4.puml` — C4 диаграмма: сбор данных из микросервисов → stream/batch обработка → DWH/Feature Store → ML/BI.

---

### Task5 — Мультитенантность, IAM, onboarding и мониторинг

Цель: дизайн мультитенантной платформы с изоляцией данных, IAM (SSO/RBAC), автоматическим onboarding партнёров и мониторингом мультитенантности.

Состав артефактов:

- `ADR-006-MultiTenant-IAM-Onboarding.md` — модель изоляции, IAM/SSO/RBAC, процесс онбординга, мониторинг мультитенантности.
- `ToBe-MultiTenant-C2.puml` — C2 диаграмма: мультитенантная платформа + IAM + мониторинг.
- `Partner-Onboarding-Flow-C3.puml` — диаграмма потока онбординга (логика и данные).
- `RBAC-Roles-Table.md` — таблица ролей и уровней доступа.

---

#### Примечание по просмотру диаграмм

Все диаграммы оформлены в формате PlantUML (`.puml`). Их можно открыть в IDE-плагине PlantUML или в любом PlantUML viewer.
